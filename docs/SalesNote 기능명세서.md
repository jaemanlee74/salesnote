# SalesNote 기능명세서

Nov 27, 2026 · @재만

## 1. 개요

SalesNote는 영업기회를 초기 탐색 단계부터 등록하고, 종료될 때까지의 진행 과정을 시간순으로 기록해 구성원과 공유하는 사내 온라인 게시판이다. 게시글 하나가 영업기회 하나에 대응하며, 단계 변경과 활동 기록이 그 글 아래에 쌓인다.

### 1.1 목적

- 담당자 개인의 메모와 메신저에 흩어진 영업 정보를 한곳에 모은다.
- 확정되지 않은 초기 정보도 부담 없이 올릴 수 있게 해 기회를 일찍 공유한다.
- 단계별 현황과 다음 할 일을 누구나 확인할 수 있게 한다.
- 수주·실주 이력을 남겨 이후 영업과 제안에 재활용한다.

### 1.2 범위

| 구분 | 내용 |
| --- | --- |
| 포함 | 영업기회 등록·수정, 단계 관리, 진행 기록(타임라인), 댓글·멘션, 첨부파일, 목록·칸반 보기, 검색·필터, 알림(서비스 내, 메일, 구글 챗), 현황 대시보드, 사용자·권한 관리 |
| 제외(1차) | 견적서·계약서 작성, 매출·정산 관리, 나라장터 공고 자동 수집, 외부 CRM·그룹웨어 연동, 전용 모바일 앱 |

### 1.3 전제

9장의 확정 사항을 반영한 전제다.

- 사용자는 VX 사업부 구성원으로 한정한다. 구글 계정으로 로그인하며 관리자가 허용한 계정만 접근한다.
- 공공조달 입찰과 민간 영업을 한 단계 흐름으로 다룬다.
- PC 웹을 기준으로 하되 모바일 브라우저에서 조회와 기록 작성이 가능한 반응형으로 만든다. 자체 개발해 AWS에 도커 컨테이너로 배포한다.
- 우선순위는 P1(1차 오픈 필수), P2(1차 오픈 권장), P3(2차 이후)로 표기한다.

## 2. 사용자 역할과 권한

역할은 네 가지이며, 영업기회는 기본적으로 VX 사업부 전 구성원에게 공개한다. 민감한 건만 작성자가 공개 범위를 좁힌다.

| 역할 | 정의 |
| --- | --- |
| 관리자 | 허용 사용자와 코드(단계, 유형, 실주 사유)를 관리하고 모든 글을 수정·삭제할 수 있다. |
| 담당자 | 영업기회를 등록한 사람 또는 담당자로 지정된 사람. 해당 기회의 정보와 단계를 바꾼다. |
| 참여자 | 담당자가 초대한 협업자. 진행 기록을 작성할 수 있다. |
| 구성원 | 관리자가 허용한 VX 사업부 사용자. 공개된 기회를 열람하고 댓글을 단다. |

## 3. 영업 단계 정의

영업기회는 진행 단계 5개와 종료 상태 3개 중 하나를 가진다. 단계 이름과 순서는 관리자가 바꿀 수 있다.

| 순서 | 단계 | 정의 | 진입 시 필수 입력 |
| --- | --- | --- | --- |
| 1 | 탐색 | 가능성을 인지한 상태. 소문, 사전 정보, 발주 계획 등 미확정 정보를 포함한다. | 제목, 고객사 |
| 2 | 접촉 | 고객 담당자와 연락·미팅이 시작된 상태. | 고객 담당자 |
| 3 | 제안 준비 | 참여를 결정하고 견적·제안서를 준비하는 상태. 공공 사업은 사전규격·공고 확인을 포함한다. | 예상 금액, 예상 일정 |
| 4 | 제안·입찰 | 견적 또는 제안서를 제출한 상태. | 제출일 |
| 5 | 협상·평가 | 평가 결과를 기다리거나 조건을 협상하는 상태. | 없음 |
| 종료 | 수주 | 계약이 확정된 상태. | 계약 금액, 계약일 |
| 종료 | 실주 | 탈락했거나 참여를 포기한 상태. | 실주 사유 |
| 종료 | 보류 | 사업이 연기되었거나 재개 시점이 불확실한 상태. | 보류 사유, 재검토 예정일 |

### 단계 전환 규칙

- 단계는 순서를 건너뛰거나 되돌릴 수 있다. 등록 시 기본값은 탐색이다. 공공과 민간은 같은 흐름을 쓰며, 사업 유형이 민간인 기회는 어느 진행 단계에서든 '바로 계약'으로 수주 처리할 수 있다.
- 단계를 바꾸면 변경 전후 단계, 변경자, 시각이 타임라인에 자동으로 남는다.
- 진입 시 필수 입력이 비어 있으면 단계 변경 화면에서 함께 입력받는다.
- 종료 상태에서도 담당자가 진행 단계로 되돌려 재개할 수 있다.
- 탐색 단계에서는 제목과 고객사만으로 등록할 수 있게 해 초기 공유의 부담을 줄인다.

## 5. 기능 상세

P1 기능 중 동작 규칙이 필요한 항목만 상세화한다.

### 5.1 영업기회 등록 (OPP-01)

- 입력: 필수는 제목과 고객사 두 가지다. 나머지는 6장의 선택 항목이다.
- 처리: 단계는 탐색, 담당자는 등록자, 공개 범위는 전체 공개로 기본 설정한다.
- 중복 방지: 고객사를 입력하면 같은 고객사의 진행 중인 기회를 보여준다. 등록을 막지는 않는다.
- 고객사 입력: 기존 고객사를 자동완성으로 고르거나 새 이름을 입력한다.
- 임시 저장: 작성 중 내용을 브라우저에 자동 보관해 이탈 후에도 이어 쓸 수 있다.
- 결과: 등록 즉시 상세 화면으로 이동하고 타임라인에 등록 기록이 생긴다.

### 5.2 단계 변경과 종료 처리 (STG-01, STG-02, STG-04)

- 상세 화면 상단에 전체 단계를 가로로 나열하고 현재 단계를 강조한다. 단계를 누르면 변경 창이 열린다.
- 변경 창은 변경 사유(선택, 200자)와 해당 단계의 필수 입력 중 비어 있는 항목을 받는다.
- 실주 처리 시 실주 사유를 코드에서 고르고 상세 내용을 적는다. 기본 코드는 가격, 기술 평가, 경쟁사 선정, 사업 취소, 참여 포기, 기타다.
- 수주 처리 시 계약 금액과 계약일을 받는다. 사업 유형이 민간인 기회는 단계 표시줄에 '바로 계약' 버튼을 두어 중간 단계를 거치지 않고 수주 처리한다.
- 종료된 기회는 목록 기본 보기에서 제외하고 종료 필터로 조회한다.

### 5.3 활동 기록과 타임라인 (ACT-01, ACT-02)

- 활동 유형은 미팅, 통화, 메일, 제안·견적, 내부 회의, 메모다.
- 입력 항목은 유형, 활동 일자(기본 오늘), 내용, 첨부파일이다. 내용은 서식 있는 텍스트를 지원한다.
- 상세 화면에서 화면 이동 없이 바로 작성한다.
- 타임라인은 사용자가 쓴 활동 기록과 시스템이 남긴 기록(단계 변경, 담당자 변경, 금액·일정 변경)을 구분해 표시한다.
- 유형별로 타임라인을 걸러 볼 수 있다.
- 기록을 작성하면 기회의 최종 갱신일이 바뀌어 목록 상단으로 올라온다.

### 5.4 다음 할 일 (ACT-03)

- 기회마다 할 일을 여러 개 등록한다. 항목은 내용, 기한, 담당자다.
- 가장 가까운 미완료 할 일을 목록과 카드에 표시한다.
- 기한이 지난 할 일은 강조 표시한다.
- 완료 처리하면 타임라인에 완료 기록이 남는다.

### 5.5 목록, 필터, 검색 (LST-01, LST-03, LST-04)

- 목록 열: 단계, 제목, 고객사, 사업 유형, 예상 금액, 담당자, 다음 할 일, 최종 갱신일, 댓글 수.
- 기본 보기는 진행 중인 기회 전체이며, 빠른 필터로 내 담당, 내가 참여, 관심 등록, 종료를 제공한다.
- 필터 조건은 주소에 반영해 같은 화면을 링크로 공유할 수 있게 한다.
- 한 페이지 20건을 기본으로 하고 50건, 100건을 선택할 수 있다.
- 검색 결과는 일치한 위치(제목, 기록, 댓글)를 표시하고 검색어를 강조한다.
- 열람 권한이 없는 비공개 기회는 목록과 검색 결과에 나오지 않는다.

### 5.6 알림 (NTF-01)

| 이벤트 | 수신자 |
| --- | --- |
| 담당자·참여자로 지정됨 | 지정된 사용자 |
| 단계 변경, 종료 처리 | 담당자, 참여자, 관심 등록자 |
| 새 활동 기록 | 담당자, 참여자, 관심 등록자 |
| 새 댓글 | 담당자, 해당 기록 작성자, 같은 글에 댓글을 단 사용자 |
| 멘션 | 멘션된 사용자 |

본인이 일으킨 이벤트는 본인에게 알리지 않는다. 알림은 상단 종 아이콘에 미확인 건수로 표시하고, 누르면 해당 기회의 해당 위치로 이동한다. 구글 챗을 연동하면 주요 알림을 지정한 스페이스로도 보낸다(NTF-04).

## 8. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 접근 통제 | 구글 계정으로 로그인한 허용 사용자만 접근한다. 비공개 기회와 열람 제한 항목은 서버에서 권한을 검사한다. |
| 보안 | 전 구간 HTTPS를 적용한다. 인증은 구글 계정 연동에 맡기고 비밀번호를 저장하지 않는다. 60분 미사용 시 자동 로그아웃한다. |
| 개인정보 | 고객 담당자 연락처는 업무 목적으로만 보관하고, 기회를 영구 삭제할 때 함께 지운다. |
| 감사 기록 | 로그인, 열람 제한 항목 조회, 삭제, 엑셀 내보내기를 기록하고 1년 보관한다. |
| 성능 | 동시 사용자 50명, 기회 5,000건 기준으로 목록과 상세 화면을 2초 이내에 표시한다. |
| 호환성 | 크롬, 엣지, 사파리 최신 2개 버전을 지원한다. 화면 폭 360px 이상에서 조회와 기록 작성이 가능하다. |
| 첨부파일 | 파일당 50MB 이하. 실행 파일 확장자는 차단한다. |
| 백업 | 데이터와 첨부파일을 하루 1회 백업하고 30일치를 보관한다. |
| 확장성 | 추가 외부 연동(그룹웨어, 입찰 공고 수집)을 대비해 주요 데이터를 API로 제공할 수 있는 구조로 만든다. |
| 구축·배포 | 자체 개발하며 AWS에 도커 컨테이너로 배포한다. |

성능·보관 기간 수치는 가정값이며 운영 환경이 정해지면 조정한다.
